# DOSSIER: ZENITH_GIT_ORCHESTRATOR

## 🌌 Overview
**ZENITH_GIT_ORCHESTRATOR** là "Hệ hô hấp" của Zenith, chịu trách nhiệm quản trị dòng thời gian và di sản mã nguồn. Nó chuyển đổi các thao tác Git thủ công thành một quy trình tự trị, đảm bảo mọi thay đổi đều được ghi vết một cách chuyên nghiệp và có nghĩa ngữ.

## 🌿 Core Mechanisms (Cơ chế Nòng cốt)

### 📝 1. Semantic Commit Generation (Sinh Commit Nghĩa ngữ)
- Zenith không viết commit sáo rỗng như "updated files". 
- Hệ thống phân tích `git diff` và đối soát với `task.md` để viết commit chuẩn **Conventional Commits**:
    - `feat:`: Tính năng mới.
    - `fix:`: Sửa lỗi.
    - `docs:`: Thay đổi tài liệu.
    - `refactor:`: Cải tiến cấu trúc nhưng không đổi tính năng.

### 🎋 2. Branch Strategy (Chiến lược Nhánh)
- Tự động hóa việc tạo và quản lý nhánh theo chuẩn `Git Flow`.
- Đảm bảo các nhánh có tiền tố rõ ràng (`feat/`, `fix/`, `hotfix/`) và liên kết trực tiếp với Task ID hoặc mã Sứ mệnh.

### 📑 3. PR & Documentation (Hồ sơ Sứ mệnh)
- Tự động tổng hợp các thay đổi thành một bản mô tả Pull Request (PR) hoàn chỉnh, bao gồm:
    - **Tóm tắt thay đổi**.
    - **Danh sách file bị ảnh hưởng**.
    - **Kết quả Test (từ TDD Autopilot)**.
    - **Ảnh hưởng kiến trúc (từ Strategic Planner)**.

## 🛠️ Operational Protocol (3 Phases)

### 🔍 Phase 1: Diff Analysis (Phân tích Khác biệt)
- Quét qua vùng `staging` để hiểu rõ những gì Master đã sửa đổi.
- Trích xuất các từ khóa quan trọng và logic thay đổi.

### 🚀 Phase 2: Message Synthesis (Tổng hợp Thông điệp)
- Soạn thảo commit message hoặc nội dung PR.
- Trình Master phê duyệt (Neural Handshake) trước khi thực thi lệnh `git commit`.

### ✅ Phase 3: Timeline Integration (Tích hợp Dòng thời gian)
- Thực thi lệnh `git push` hoặc `git merge`.
- Cập nhật nhật ký hệ thống để đảm bảo tính đồng bộ di sản.
