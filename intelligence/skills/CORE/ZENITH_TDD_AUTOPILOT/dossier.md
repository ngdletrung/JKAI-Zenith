# DOSSIER: ZENITH_TDD_AUTOPILOT

## 🌌 Overview
**ZENITH_TDD_AUTOPILOT** là "Xương sống Kỹ thuật" của Zenith, đảm bảo mọi dòng mã được sinh ra đều có bảo chứng bằng kiểm thử (Test-Proven Code). Lấy cảm hứng từ quy trình khép kín của Claude Code, kỹ năng này tự động hóa hoàn toàn vòng lặp **Red-Green-Refactor**.

## 🧪 The TDD Cycle (Chu trình Autopilot)

### 🔴 1. Phase RED (Sinh Test & Xác nhận Lỗi)
- Dựa trên mô tả tính năng của Master, Zenith tự động viết các Test Case bao phủ mọi trường hợp (Success, Failure, Edge Cases).
- Chạy test lần đầu để xác nhận nó **Thất bại** (đảm bảo test có giá trị).

### 🟢 2. Phase GREEN (Thực thi Logic)
- Zenith viết mã nguồn tối giản nhất để vượt qua các bài test.
- Chạy lại test loop cho đến khi toàn bộ đèn xanh (All Tests Passed).

### 🔵 3. Phase REFACTOR (Tối ưu hóa)
- Sau khi code đã chạy đúng, Zenith thực hiện tối ưu hóa cấu trúc mã nguồn theo chuẩn Clean Code mà vẫn đảm bảo các bài test vẫn pass.

## 🛠️ Intelligent Features (Tính năng Thông minh)

### 🔍 Framework Auto-Detection
- Tự động nhận diện hệ sinh thái của dự án để sử dụng công cụ kiểm thử phù hợp (Pytest cho Python, Jest cho Node.js...).

### 🩹 Self-Healing (Tự chữa lành)
- Nếu test thất bại do lỗi cú pháp hoặc logic sai, Zenith tự động đọc Traceback, phân tích nguyên nhân và thực hiện bản vá Micro-patching cho đến khi thành công.

### 📊 Coverage Mastery
- Đảm bảo tỉ lệ bao phủ (Coverage) luôn đạt mức tối ưu, không để sót các nhánh logic quan trọng.

## ⚖️ Sovereign Laws
- **Luật Thực chứng**: Không có tính năng nào được coi là hoàn tất nếu không có bộ test đi kèm.
- **Luật Kỷ luật**: Test phải chạy độc lập, không phụ thuộc vào trạng thái môi trường bên ngoài (Mocks/Stubs).
